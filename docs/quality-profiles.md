# Quality profiles and resource assumptions

These are initial measurable limits, not claims about the quality obtainable
from every capture. Validation treats triangle count, texture count, and
texture dimensions as hard limits. Package, RAM, and VRAM figures are planning
estimates and are written to the run manifest.

| Profile | Target / maximum triangles | Texture limit | Estimated package | Estimated Blender RAM / VRAM |
|---|---:|---:|---:|---:|
| high | 6.0M / 8.0M | ≤256 images, ≤8192 px each, ≤512 MP total, PNG | 2.5 GB | 10 / 8 GB |
| medium | 1.5M / 2.0M | ≤256 images, ≤4096 px each, ≤256 MP total, PNG | 0.8 GB | 5 / 3.5 GB |
| low | 350k / 500k | ≤256 images, ≤2048 px each, ≤128 MP total, JPEG 88 | 0.25 GB | 2 / 1.8 GB |

The low estimate leaves 2.2 GB of a 4 GB viewing budget for Blender, the
viewport, transient buffers, and driver overhead. The medium viewing budget is
configurable (`quality.medium_vram_gb`) because “RTX 5070” alone does not
identify memory capacity. The initial 8 GB default is conservative and is not
an assertion about the user's card.

## Measurement method

The estimates assume indexed triangles with positions, normals, one UV set,
material assignments, mipmaps generated by the viewer, and approximately 1.33×
texture memory for a complete mip chain. The total-megapixel bounds prevent a
large count of small MVS atlases from being treated like the same count of
maximum-size images. Package estimates use actual archive sizes once generated.
Viewing estimates should be replaced after loading each asset in Blender and
recording peak process RSS and GPU memory. The manifest keeps the configured
estimates separate from measured values.

Simplification uses Blender's collapse decimator with UV/material data retained.
Textures are resized per profile and exported with relative OBJ paths and as
embedded GLB resources. The independent Blender validation fails a profile if
the importer sees too many triangles, images, or oversized images. It also
checks materials, non-finite geometry, and OBJ portability.

## Benchmark status

An anonymous 20-image, 12-megapixel DNG subset was run in the two-T4/30 GB
target-shaped runtime at a 1600-pixel working dimension. All 20 images
registered; dense fusion produced 685,525 points; Poisson output contained
4,203,573 faces; and MVS-Texturing produced 99 atlases totaling about 31 MP.
The atlas-count limits were revised from the unmeasured initial assumptions,
while total texture pixels were added as the resource-relevant hard bound.
The private images, location metadata, URL, and credentials are not recorded.

This subset is evidence for orchestration and initial bounds, not a guarantee
for every 500-image capture. Each production run remains subject to the same
hard validations, and the manifest records its actual dimensions and counts.
